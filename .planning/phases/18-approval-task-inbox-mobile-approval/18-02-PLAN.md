<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → `/api/v1/approval/tasks` | Untrusted query params and action payloads cross into assignee-scoped approval data |
| approver remark events → applicant own-detail | Internal processing notes must not cross into applicant-visible timeline payloads |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-04 | E/I | task list/detail/action service | mitigate | Scope every read by `assigneeId = actor.id`, keep approve/reject stale-task checks delegated to `approveTask` / `rejectTask`, and expose handled history from task rows instead of broad application queries |
| T-18-05 | T | action route bodies | mitigate | Accept only `comment` with TypeBox `additionalProperties: false`; never accept applicant identity, snapshot, or status fields from clients |
| T-18-06 | I | applicant own-detail timeline | mitigate | Mark internal remarks with `payload.visibility = 'INTERNAL'` and filter them out in `application-submission.service.ts` before own-detail serialization |
| T-18-07 | T | task filters | mitigate | Normalize numeric/date filters and build Prisma `where` objects only; do not interpolate raw filter strings into SQL |
</threat_model>
