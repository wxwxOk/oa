<action>
Create `frontend/src/components/visit/visitImport.ts` and `frontend/src/components/visit/__tests__/visitImport.test.ts`.

In `visitImport.ts`, export these functions:

- `parseVisitImportRows(rows: unknown[][], fileName?: string): VisitImportPreview`
- `validateVisitImportHeaders(actualHeaders: unknown[]): { headerValid: boolean; expectedHeaders: string[]; actualHeaders: string[]; headerErrors: string[] }`
- `normalizeExcelDate(value: unknown): string | null`
- `buildVisitDuplicateWarnings(validRows: VisitImportValidRow[]): VisitImportDuplicateWarning[]`

Implement exact behavior:

- Treat `rows[0]` as ignored title row and `rows[1]` as the header row.
- Validate `rows[1]` against `VISIT_IMPORT_HEADERS` with exact order and exact trimmed text.
- If a header differs, set `headerValid: false`, add messages containing `第 ${index + 1} 列`, `期望`, `实际`, the expected header and actual header, and do not emit valid rows.
- Parse data from `rows[2]` onward and report row numbers as the original Excel row number `index + 1`.
- Skip data rows where every cell is blank after trimming.
- Map columns to `VisitWritePayload` fields in this order: `name`, `age`, `education`, `gender`, `channelPartner`, `consultant`, `receptionStatus`, `receptionist`, `receptionDate`, `consultationStatus`, `statusCategory`, `statusDescription`, `trialStatus`, `solution`, `trialDate`.
- Trim string fields and convert blank optional fields to `null`.
- Require `name` after trim; invalid rows contain an error with field `姓名` and message `不能为空`.
- Accept blank `age` as `null`, accept integer numeric/string age as a number, and reject decimal or non-numeric age with field `年龄` and message `必须是整数`.
- Normalize `receptionDate` and `trialDate` to `YYYY-MM-DD`; accept blank as `null`, `Date` values, Excel serial numbers and common strings like `2026-05-02`, `2026/05/02`.
- Convert Excel serial number `46144` to `2026-05-02` using the Excel 1900 date system base `1899-12-30`.
- Do not call `toISOString()` for business date output.
- Invalid date rows contain field `接待日期` or `试听课时间` and message `必须是有效日期`.
- If a row has any error, add it to `invalidRows` and do not add it to `validRows`.
- Generate duplicate keys only when `name`, `receptionDate` and `consultant` are all non-empty; key format is `${name}|${receptionDate}|${consultant}`.
- `duplicateWarnings` groups duplicate valid rows by key and lists all duplicate `rowNumbers`; duplicate warnings must not remove rows from `validRows`.

In `visitImport.test.ts`, add Vitest tests covering:

- row 1 title ignored and row 2 exact headers pass.
- header mismatch returns `headerValid: false`, `validRows.length === 0`, and a `headerErrors` item containing `第 2 列`, `期望`, and `实际`.
- blank data rows are skipped.
- valid row at Excel row 3 is normalized with trimmed strings, blank optional fields as `null`, integer age and `YYYY-MM-DD` dates.
- Excel serial `46144`, string `2026/05/02`, and `Date` values normalize to `YYYY-MM-DD`.
- invalid rows for blank name, decimal age and invalid dates preserve original Excel row numbers.
- duplicate warnings by `姓名 + 接待日期 + 咨询师` include both row numbers and do not invalidate rows.
</action>

<threat_model>
- The highest-risk defect is using SheetJS object mode or row 1 as headers; tests must pin array-of-arrays row offsets.
- Excel date serial conversion can drift by timezone or off-by-one; parser output must be `YYYY-MM-DD` strings and tests must include serial `46144 -> 2026-05-02`.
- Duplicate warnings are intentionally not validation errors; do not drop or mutate valid rows when duplicates are found.
- Do not add backend upload, backend Excel parsing, `skipDuplicates`, unique constraints, status dictionaries or export helpers.
</threat_model>
