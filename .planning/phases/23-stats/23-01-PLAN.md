# Phase 23 Plan 01: Visit Stats Backend DTO and Contracts

<objective>
Upgrade the existing `/api/v1/visits/stats` backend contract from simple counts to an enriched, test-covered statistics DTO that can directly drive the Phase 23 frontend panel.
</objective>

<context>
Phase 20 already added the `/visits/stats` endpoint, `visit:stats` guard, reception-date filtering and keyword helpers. This plan keeps that route and permission boundary, then refines `buildVisitStats` so channel/person dimensions include conversion counts and rates while status fields remain simple distributions.
</context>

<action>
Update `backend/src/modules/visit/visit.route.ts`.

Implement the Phase 23 stats DTO without changing the route path, HTTP method or permission guard:

- Keep `GET /stats` under `new Elysia({ prefix: '/visits' })`.
- Keep `.use(authGuard('visit:stats'))` as the stats route guard.
- Keep date filtering limited to `dateFrom` / `dateTo` on `receptionDate` through `buildDateFilter(query)`.
- Export reusable types if useful for tests: `VisitStatsRow`, `VisitStatsDimensionRow`, `VisitStatsDistributionRow`, `VisitStatsResponse`.
- Add a constant or helper for the blank bucket `未填写`.
- Add a rate helper that returns numeric percentages rounded to one decimal: denominator `0` returns `0`; otherwise use `Math.round((numerator / denominator) * 1000) / 10` or equivalent.
- Replace the old `groupByField` behavior with two focused helpers:
  - dimension grouping for `channelPartner`, `consultant`, `receptionist` that calculates `name`, `count`, `total`, `intentCount`, `signedCount`, `intentRate`, `signedRate`.
  - distribution grouping for `receptionStatus`, `consultationStatus`, `statusCategory`, `trialStatus` that calculates `name`, `count`.
- Normalize grouping names with trim; use `未填写` for null, undefined, empty or whitespace-only values.
- Sort dimension rows by `total` descending, then `name` ascending; sort distribution rows by `count` descending, then `name` ascending.
- Return top-level `total`, `intentCount`, `signedCount`, `intentRate`, `signedRate`, `byChannelPartner`, `byConsultant`, `byReceptionist`, `byReceptionStatus`, `byConsultationStatus`, `byStatusCategory`, and `byTrialStatus`.
- Keep `isIntentVisit` and `isSignedVisit` as the single conversion source; do not duplicate conversion rules in the route handler.
- Do not introduce enum/dictionary tables, configurable conversion rules, raw SQL, Excel export, report download, new permissions or a new stats endpoint.
</action>

<threat_model>

- Blank values must not vanish from grouped totals; test `未填写` buckets for both dimensions and status distributions.
- Date range behavior must stay reception-date-only with inclusive `dateTo` end-of-day handling.
- Do not turn Phase 23 into BI infrastructure: no dictionaries, editable rules, exports, report persistence, sales funnel workflows or public signup.
</threat_model>
