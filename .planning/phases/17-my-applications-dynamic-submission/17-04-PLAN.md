<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| employee UI -> approvalApplication store | User can manipulate form fields, route ids, filters, and repeated clicks |
| route/menu permission gates -> backend authorization | Client gating improves UX but backend remains authoritative |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-01 | I/E | route/menu/list/form access | mitigate | Add route `meta.perm` and menu `perm` for own applications; pages use only own store endpoints and never department/all filters. |
| T-17-02 | T | submit button handler | mitigate | Call `GridFormRenderer.validateFields()` and `saveSignatures()` before `store.submit`; backend required validation remains authoritative. |
| T-17-03 | T/R | save draft button handler | mitigate | Save draft calls store draft endpoints only and does not call submit; UI copy distinguishes `保存草稿` from `提交申请`. |
| T-17-04 | T/E | form page data loading | mitigate | Form page uses template/draft data returned by backend; it never constructs or sends schema/process snapshots. |
| T-17-06 | D | save/submit actions | mitigate | Bind Quasar button `loading`/`disable` to store action state to prevent duplicate clicks; backend rejects invalid transitions. |
</threat_model>
