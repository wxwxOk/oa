<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| route id -> detail fetch | User can alter `:id`; backend must enforce ownership and frontend must not present department/all controls |
| cancel button -> cancel API | User can click repeatedly or attempt terminal/draft cancellation |
| snapshot rendering -> dynamic renderer | Historical schema/data are backend-provided and must not be replaced with current template data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-01 | I/E | detail route and list navigation | mitigate | Detail page calls own `fetchDetail(id)` only; no all/dept query params; backend ownership errors are shown as load failures. |
| T-17-04 | T | read-only form renderer | mitigate | Detail renders `detail.schemaSnapshot` + `detail.formData`; it does not load current template schema for historical applications. |
| T-17-06 | D/T | cancel confirmation and handler | mitigate | Show cancel only when `canShowCancelAction(detail)` is true; bind loading state to prevent duplicate requests; refresh detail/list after success. |
| T-17-03 | R | draft/detail action confusion | mitigate | Draft records do not show cancel; draft action remains `继续填写`, not cancel. |
</threat_model>
