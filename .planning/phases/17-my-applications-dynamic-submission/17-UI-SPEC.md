## Scope Boundary

Phase 17 UI includes:
- Employee navigation entry for `我的申请`.
- Approval template picker for starting internal applications.
- Dynamic application form with save-draft and submit actions.
- My Applications list with status/date filters.
- Application detail with read-only form snapshot, status summary, current node, timeline, comments, and visibility hint.
- Applicant cancel flow for non-terminal submitted/approving applications.

Phase 17 UI excludes:
- Approver task handling, approve/reject opinion entry, and handled-history views.
- Archive search, export, statistics, tags, internal remarks, post-submit editing, processing fields, attachments, and notifications.
- Public `/f/:code` collection flow changes.

Source: `17-CONTEXT.md` D-01 through D-25 and Requirements `APP-01` through `APP-05`.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge gaps, field helper spacing |
| sm | 8px | Compact action gaps, card internal metadata gaps, timeline item spacing |
| md | 16px | Default `q-page padding`, form sections, filter row gaps, mobile card padding |
| lg | 24px | Header-to-content spacing, detail section spacing, desktop card sections |
| xl | 32px | Desktop form/detail two-column gap, large dialog inner grouping |
| 2xl | 48px | Empty, loading, and error state vertical padding |
| 3xl | 64px | Public-fill-style desktop vertical breathing room only when centering the new application form |

Exceptions:
- `44px` minimum touch target for mobile primary buttons, bottom actions, date pickers, template rows, and cancel controls.
- `1px` borders for `flat bordered` cards, tables, drawers, timeline separators, and form section dividers.
- Existing `FilterSheet` bottom sheet may keep its 16px top corner radius; normal cards stay at 8px radius or less.
- No new arbitrary spacing values beyond existing Quasar spacing classes unless inherited from reused renderer components.

## Typography

Use exactly two weights: regular `400` and semibold `600`.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Caption / metadata | 12px | 400 | 1.5 |
| Body / table row | 14px | 400 | 1.5 |
| Section / card title | 16px | 600 | 1.4 |
| Page / dialog heading | 20px | 600 | 1.2 |

Rules:
- Page titles use existing `.text-h6` override: 20px, 600, 1.2.
- Mobile card primary text may use Quasar `text-subtitle1` but must render at 16px or below, never hero-scale.
- Form labels, required marks, helper copy, and validation messages reuse `FieldRenderer` sizing.
- Long template names, application numbers, node names, and comments must wrap on 375px screens without horizontal overflow.

| Accent (10%) | Light `#4F46E5` / Dark `#6366F1` | Reserved elements listed below |

Accent reserved for:
- Primary CTAs: `发起申请`, `提交申请`, `选择模板`, `重新加载`.
- Active navigation item `我的申请` under `审批管理`.
- Active status/date filters in `q-btn-toggle` or selected filter chips.
- Focus rings on `q-input`, `q-select`, date inputs, template picker rows, and keyboard-focused action buttons.
- Non-destructive action icons: view detail, continue draft, save draft, template select.
- Active processing state chip `审批中`.

Status colors:

| Status | Display Label | Component | Color Contract |
|--------|---------------|-----------|----------------|
| `DRAFT` | 草稿 | `q-chip` / `q-badge` | `color="warning" text-color="white"` |
| `SUBMITTED` / `APPROVING` | 审批中 | `q-chip` / `q-badge` | `color="primary" text-color="white"` |
| `APPROVED` | 已通过 | `q-chip` / `q-badge` | `color="positive" text-color="white"` |

## Layout And Component Contract

### Navigation

- Add `我的申请` under existing `审批管理` in `MainLayout.vue`.
- Route: `/approval/applications`.
- Icon: material icon `assignment`.
- Visibility permission: `approval:application:own`.
- The create action uses `approval:application:create`; users without it can still view their own list if `approval:application:own` is present.
- Keep `流程配置` under the same group; do not add approver or archive entries in Phase 17.

### My Applications Page

Use the existing admin/list pattern from `SubmissionPage.vue`, `TemplatePage.vue`, and `ApprovalProcessPage.vue`.

Desktop layout:
- Container: `q-page padding`.
- Header: left title `我的申请`, right primary CTA `q-btn color="primary" icon="add" label="发起申请"` gated by `approval:application:create`.
- Filters: horizontal `row items-center q-gutter-sm q-mb-md`.
- Status filter: `q-btn-toggle toggle-color="primary" flat bordered` with `全部 / 草稿 / 审批中 / 已通过 / 已驳回 / 已撤销`.
- Date filters: two dense outlined date inputs labeled `开始日期` and `结束日期`, each using `q-popup-proxy` + `q-date` with `YYYY-MM-DD`.
- Optional keyword search may be application number or template name only, placeholder `搜索申请编号/模板`.
- Data view: `q-table flat bordered dense`, row-key `id`, pagination `[10, 20, 50]`, default sorted by latest `updatedAt` or `createdAt` descending.

Desktop table columns:

| Column | Label | Width | Content |
|--------|-------|-------|---------|
| applicationNo | 申请编号 | 140px | stable backend-generated application number |
| templateName | 申请类型 | auto | template snapshot name + `v{templateVersion}` caption |
| status | 状态 | 96px | status chip from color contract |
| currentNodeName | 当前节点 | 160px | node name, or `—` for draft/terminal states |
| updatedAt | 更新时间 | 160px | `YYYY-MM-DD HH:mm` |
| actions | 操作 | 120px | view detail, continue draft when applicable |

Mobile layout:
- Header stays one row: title `我的申请` + icon button/CTA for `发起申请`.
- Filters collapse into a bottom `q-dialog position="bottom"` sheet or a page-specific `FilterSheet` variant.
- Mobile cards use `q-card flat bordered` with 8px radius or less.
- Card top row: template name + status chip.
- Card metadata: application number, current node, updated/submitted time.
- Card action row: `继续填写` for `DRAFT`, `查看详情` for non-draft; tapping a card opens the same target.

### Start Application Template Picker

- Triggered by `发起申请`.
- Desktop: `q-dialog` width `720px`, max-width `calc(100vw - 32px)`.
- Mobile: maximized dialog or full page route.
- Title: `发起申请`.
- Content lists only `PUBLISHED + APPROVAL_REQUIRED` templates with enabled valid process bindings.
- Template item content: template name, optional description, process name, schema version, and `选择模板` action.
- Use `q-list`/`q-item` or compact `q-card flat bordered`; avoid decorative template cards.
- Empty state icon `assignment`, heading `暂无可发起申请`, body `当前没有已发布且绑定审批流程的模板，请联系管理员。`
- Selecting a template routes to the internal form. Do not route to public `/f/:code`.

### Dynamic Application Form

- Route may be `/approval/applications/new/:templateId` for new applications and `/approval/applications/:id/edit` for draft continuation.
- Container follows `PublicFillPage.vue` form ergonomics but inside authenticated layout.
- Desktop form max width: `960px`; centered within `q-page padding`.
- Header: back button, template name, `v{templateVersion}` caption, optional description.
- Identity fields are not shown for logged-in applicants. Show a read-only applicant snapshot row instead: `申请人：{applicantName}` and `部门：{departmentName || '未设置部门'}`.
- Dynamic fields use `GridFormRenderer mode="fill"` with the schema snapshot for drafts and template schema for new applications.
- Formal submit must call `GridFormRenderer.validateFields()` and `saveSignatures()` before API submit.
- Save draft does not block on required-field completion; it may validate only data shape and signature serialization.

Form actions:
- Desktop: bottom action row inside the form surface, right aligned.
- Mobile: sticky bottom action bar with safe-area padding, following `PublicFillPage.vue` `submit-section`.
- Secondary action: `保存草稿`, `q-btn outline color="primary"`, loading while saving.
- Primary action: `提交申请`, `q-btn color="primary"`, loading while submitting.
- Cancel/back action: flat `返回`.
- Async actions disable duplicate submits and keep entered data in place on failure.

### Application Detail

Use a full page detail route rather than a narrow drawer because Phase 17 detail includes both dynamic form data and timeline.

- Route: `/approval/applications/:id`.
- Desktop layout: `q-page padding`, max content width `1184px`, two columns.
- Left column: application summary + read-only form snapshot.
- Right column: current node + approval timeline.
- Mobile layout: single column; timeline follows the summary before or after form, but never overlays sticky actions.
- Header: back button, title `申请详情`, status chip, optional destructive `撤销申请` button when allowed.
- Summary fields: application number, template snapshot name/version, applicant snapshot, department snapshot, submitted time, completed time, current node.
- Visibility hint: `仅展示与你本人申请相关的表单数据、审批节点和审批意见。`
- Form rendering: `GridFormRenderer mode="print"` with `ApprovalApplication.schemaSnapshot` + `formData`; never use the current template schema for historical applications.
- Detail must show `—` for missing values rather than blank cells.

Timeline:
- Use `q-timeline` or a bordered vertical `q-list` with identical spacing and text.
- Timeline order: oldest to newest.
- Each item shows title, actor name, node name when present, comment when present, and timestamp.
- Event labels:
  - `SUBMIT`: `提交申请`
  - `ASSIGN`: `进入 {nodeName}`
  - `APPROVE`: `审批通过`
  - `REJECT`: `审批驳回`
  - `CANCEL`: `撤销申请`
- Phase 17 displays existing events only; no opinion input, internal remark input, labels, marks, or processing fields.

### Cancel UX

- `撤销申请` is visible only for the applicant's own `SUBMITTED` or `APPROVING` application.
- `DRAFT`, `APPROVED`, `REJECTED`, and `CANCELED` states do not show this action.
- Desktop button: header right, `q-btn outline color="negative" icon="cancel" label="撤销申请"`.
- Mobile button: in a sticky bottom action area on detail, `min-height: 44px`.
- Confirmation uses persistent `Dialog.create` or `q-dialog`.
- Dialog title: `撤销申请`.
- Dialog body: `撤销后当前审批待办将关闭，审批人不能继续处理。此操作会记录在时间线中。`
- Optional reason field: `撤销原因（选填）`, textarea, max 200 characters.
- Confirm button: `确认撤销`, `color="negative"`.
- Success feedback: `Notify positive` with `申请已撤销`; refresh detail and list state.

## State Matrix

| State | Visual Contract |
|-------|-----------------|
| Initial list loading | Desktop: `q-skeleton` table header + 5 rows. Mobile: 3 bordered card skeletons. |
| Filter/page loading | Keep filters visible; `q-table :loading="true"` or card-list inline skeleton. |
| Empty applications | `EmptyState` icon `assignment`, heading/body from copy contract, CTA `发起申请` when permitted. |
| List network error | Centered message `我的申请加载失败，请检查网络后重试。` + `重新加载` primary button. |
| List data | Desktop table or mobile cards with application number, template name, status, current node, updated time, and action. |
| Template picker loading | Skeleton list rows with stable height. |
| Template picker empty | `EmptyState` copy for no available approval templates; no fallback to public collection templates. |
| New form loading | Public-fill-style form skeleton: title lines + 3 field rectangles. |
| Draft editing | Form populated from draft `schemaSnapshot` and `formData`; actions show `保存草稿` and `提交申请`. |
| Save draft success | `Notify positive` `草稿已保存`; remain on form or update route to draft id. |
| Submit validation failure | Field-level renderer errors remain visible; show `Notify negative` `请完善必填项后再提交申请。` only once per submit attempt. |
| Submit success | `Notify positive` `申请已提交`; navigate to application detail. |
| Detail loading | Summary skeleton + form section skeleton + timeline skeleton. |
| Detail data | Summary, read-only form snapshot, timeline, and visibility hint all visible without entering edit mode. |
| Cancel allowed | `撤销申请` visible in detail header/mobile sticky area for `SUBMITTED` or `APPROVING`. |
| Cancel blocked | Button hidden for draft and terminal states; backend rejection shows `Notify negative` with server reason. |
| Cancel success | Status chip changes to `已撤销`; timeline includes `撤销申请`; pending actions disappear. |

## Accessibility And Interaction Rules

- All icon-only buttons must have `aria-label` or `q-tooltip`: back, view detail, continue draft, date picker, close dialog, cancel.
- Keyboard tab order follows visual order: page CTA, filters, table/card actions, form fields, form actions, detail cancel.
- Focus ring uses existing global `--oa-focus-ring`; do not remove Quasar focus outlines.
- Mobile touch targets are at least 44px high for template rows, filter controls, sticky form actions, and cancel action.
- Status is always displayed as text plus color; color alone is not sufficient.
- Loading buttons set `loading` and prevent duplicate save, submit, and cancel requests.
- Long comments and template names use `word-break: break-word` or normal wrapping; no horizontal scroll on 375px except inside existing dynamic table desktop wrapper.
- Timeline comments preserve line breaks and wrap within the column.
- Mobile sticky action bars include `env(safe-area-inset-bottom, 0px)` padding.
- Hover states use background/border color only and must not shift layout.
