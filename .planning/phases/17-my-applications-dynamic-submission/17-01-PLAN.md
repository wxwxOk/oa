<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| employee client -> service helpers | Client may provide template id, application id, formData, filters, or cancel reason, but never trusted snapshots or applicant identity |
| service helpers -> Prisma approval aggregate | Service writes draft/application/task/timeline data and must preserve Phase 15 state-machine guarantees |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-01 | I/E | `getOwnApplicationDetail`, `updateDraftApplication`, `submitDraftApplication`, `cancelOwnApplication` | mitigate | Always query by both `id` and `applicantId`, or explicitly compare `actor.id` before mutation; tests must prove non-applicant access is rejected. |
| T-17-02 | T | `submitDraftApplication` | mitigate | Run `validateFormDataRequiredFields(application.schemaSnapshot, formData)` on formal submit only; tests must prove missing required fields reject before task creation. |
| T-17-03 | T/R | `createApplicationDraft`, `updateDraftApplication` | mitigate | Draft create/update only writes `ApprovalApplication` with `DRAFT` status and zero task/action/timeline rows; tests must assert counts remain zero. |
| T-17-04 | T/E | `createApplicationDraft` | mitigate | Load template/process/user/department from Prisma and call `resolveProcessSnapshot`; service input must not accept `schemaSnapshot`, `processSnapshot`, `applicationNo`, applicant name, or department snapshot from the client. |
| T-17-06 | D/T | `submitDraftApplication`, `cancelOwnApplication` | mitigate | Reuse `submitApplication` and `cancelApplication` state-machine transactions; reject non-draft duplicate submits and terminal/draft cancel attempts with existing `BizError` behavior. |
</threat_model>
