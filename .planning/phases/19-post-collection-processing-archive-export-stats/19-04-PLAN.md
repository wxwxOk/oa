<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| frontend store->archive API | Client sends untrusted filters and operation payloads to backend services. |
| frontend route guard->navigation | Client-side visibility improves UX but cannot be the security boundary. |
| frontend store->notification API | Client polls and marks current-user notification state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-IDOR | I/E | approvalArchive store | mitigate | Store carries source identifiers only; backend plans perform source-specific authorization. |
| T-19-TAMPER | T | payload key constants | mitigate | Type constants and tests exclude trusted fields from operation payloads. |
| T-19-AUDIT | R/T | approvalArchive store | mitigate | Store routes all changes through backend action endpoints that append audit events. |
| T-19-CSV-INJECTION | T/I | exportExcel | mitigate | Store calls server export only; backend export plan sanitizes cells. |
| T-19-EXPORT-DOS | D | exportExcel | mitigate | Store handles row-cap error copy; backend export plan enforces 2,000 rows. |
| T-19-NOTIFICATION-LEAK | I | notification store | mitigate | Store never sends target user IDs; backend plan constrains by current user. |
| T-19-DATA-SEPARATION | T/I | archive DTOs | mitigate | Types model `formalData`, `effectiveData`, `processingData`, and `correctionHistory` separately. |
</threat_model>
