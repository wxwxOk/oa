## Scope Boundary

Phase 19 UI includes:
- A unified `归档查询` entry under `审批管理`.
- Archive query list for approval applications and public collection submissions, normalized by `sourceType`.
- Archive detail full page with formal submitted content, tags/marks, internal notes, processing fields, controlled edit history, and export actions.
- Tag/mark management using recommended quick tags plus free text.
- Internal note entry and timeline/event display for authorized staff.
- Controlled post-submit correction with mandatory reason and field-level before/after history.
- Template processing-field configuration for lightweight internal fields.
- Excel export for the currently filtered list under the current user's permissions.
- Single-record print/PDF reuse of the existing `#print-area` and `GridFormRenderer mode="print"` path.
- Basic archive statistics by template, status, department, month, and source type.
- In-app notification badge/list for new tasks and final approval results.

Phase 19 UI excludes:
- Applicant-visible exposure of internal notes, tags, processing fields, or edit overlays.
- Attachments, image/file previews, attachment export, and evidence material workflows.
- External notification channels such as WeCom, DingTalk, SMS, and email.
- Full BI dashboards, field-level analytics, amount aggregation, forecasting, custom reports, or saved filter builders.
- Dedicated tag taxonomy management, template-level tag dictionaries, and tag color governance.
- WebSocket/SSE realtime notification delivery.
- Batch PDF for approval archive records beyond existing collection behavior.

Sources: `19-CONTEXT.md` D-01 through D-30, `REQUIREMENTS.md` OPS-01 through OPS-07, `ROADMAP.md`.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, compact chip gaps, helper text separation |
| sm | 8px | Filter control gaps, mobile card internal gaps, table action gaps |
| md | 16px | Default page padding, card padding, dialog content spacing, bottom sheet gaps |
| lg | 24px | Desktop section spacing, archive detail column gap, stats card gap |
| xl | 32px | Major page section separation and page-header-to-content spacing |
| 2xl | 48px | Empty/error/loading vertical padding |
| 3xl | 64px | Large empty-state breathing room only |

Exceptions:
- `44px` minimum touch target for mobile filter trigger, bottom sheet controls, mobile card actions, notification icon button, edit/note/tag actions, and sticky/mobile primary actions.
- `56px` minimum row height for tappable mobile records, notification rows, and processing-field rows with icon + label.
- `1px` borders for cards, tables, dialogs, sticky bars, print tables, and separators.
- `12px` is allowed inside dense summary grids and dialog warning blocks where existing Phase 18 detail pages already use it.
- Stats chart container height is fixed at `300px`.
- Mobile sticky regions use `16px` horizontal padding and `16px + env(safe-area-inset-bottom, 0px)` bottom padding.
- Archive detail pages reserve at least `112px` bottom padding on mobile when sticky actions are visible.

## Typography

Use exactly two weights: regular `400` and semibold `600`.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Caption / metadata | 12px | 400 | 1.5 |
| Body / table cell / form value / note text | 14px | 400 | 1.5 |
| Section / card title | 16px | 600 | 1.4 |
| Page / dialog heading | 20px | 600 | 1.2 |

Rules:
- Page titles and dialog titles use the existing `.text-h6` override at 20px, 600, 1.2.
- Mobile card primary text may use Quasar `text-subtitle1` but must render at 16px or below.
- Archive IDs, template names, applicant/filler names, tags, note content, field names, field values, and edit reasons must wrap on 375px screens without horizontal overflow.
- Timeline metadata stays at 12px; note/comment bodies stay at 14px with `white-space: pre-wrap`.
- Button text uses Quasar defaults; do not create hero-sized CTAs in this operational workflow.
- Print/PDF detail may keep the existing print typography from Phase 9/13: 16pt title, 12pt metadata/body, 12pt semibold labels.

## Layout And Component Contract

### Navigation

- Add `归档查询` under existing `审批管理` in `MainLayout.vue`.
- Route: `/approval/archive`.
- Icon: material icon `inventory_2`.
- Visibility permission: show when user has any archive-view capability derived from `approval:application:department`, `approval:application:all`, or `form:submission:list`; action-level controls still obey stricter permissions.
- Menu order under `审批管理`: `待我审批`, `我的申请`, `归档查询`, `流程配置`.
- Add a notification icon button in the header near dark mode/user controls:
  - Icon: `notifications`.
  - `aria-label`: `站内通知`.
  - Floating unread `q-badge` shows `99+` when unread count exceeds 99.
  - On mobile, notification access stays in the top toolbar, not the bottom tab bar.

### Archive Query List

Desktop layout:
- Container: `q-page padding`.
- Header left: title `归档查询`; secondary line `查询审批申请和公开收集记录的后续处理状态`.
- Header right actions:
  - `刷新` icon button.
  - `导出 Excel` primary button, visible with `approval:export`.
- Primary query control row below header:
  - Source type `q-btn-toggle`: `全部 / 审批申请 / 公开收集`.
  - Status `q-select` or `q-btn-toggle`: `全部 / 审批中 / 已通过 / 已驳回 / 已撤销 / 已收集`.
  - Template `q-select`, label `模板`.
  - Department `q-select`, label `部门`.
  - Person `q-input`, label `申请人/填写者`.
  - Date range: `开始日期`, `结束日期`.
  - Tag filter `q-select`, label `标签/标记`, multiple chips.
  - `查询归档` primary button and `重置筛选` flat button.
- Data view: `q-table flat bordered dense`, rows-per-page `[10, 20, 50]`, default sort by recent update/completion time descending.
- Keep table density operational; do not wrap table in decorative cards.

Desktop table columns:

| Column | Label | Width | Content |
|--------|-------|-------|---------|
| archiveNo | 编号 | 140px | approval application number or collection record ID fallback |
| sourceType | 来源 | 96px | source chip `审批申请` or `公开收集` |
| templateName | 模板 | auto | template name + `v{schemaVersion}` caption when available |
| person | 申请人/填写者 | 180px | person name on first line, phone or account caption when available |
| department | 部门 | 140px | department or `未设置部门` |
| status | 状态 | 104px | status chip with Chinese label |
| tags | 标签/标记 | 180px | up to 3 visible chips, overflow text `+{n}` |
| processingSummary | 处理信息 | 160px | latest processing field summary or `—` |
| updatedAt | 更新时间 | 160px | `YYYY-MM-DD HH:mm` |
| actions | 操作 | 128px | `查看详情` and row menu for allowed operations |

Mobile layout:
- Header contains title, notification count remains in global toolbar, and one round `filter_list` button for the filter sheet.
- Archive records use `q-card flat bordered` in a vertical list.
- Card information order:
  1. Template name
  2. Source chip + status chip
  3. Record number
  4. Applicant/filler and department
  5. Tags/marks
  6. Latest processing summary
  7. Updated time
- Entire card is tappable and routes to the archive detail.
- Card action row contains one primary text button `查看详情`; additional operations are inside detail, not row quick edits.

### Mobile Filter Sheet

- Use `q-dialog position="bottom"` with a `q-card` sheet and top drag handle.
- Sheet title: `筛选归档`.
- Controls are stacked with `16px` gaps:
  - 来源
  - 状态
  - 模板
  - 部门
  - 申请人/填写者
  - 开始日期
  - 结束日期
  - 标签/标记
- Buttons:
  - Secondary: `重置筛选`
  - Primary: `应用筛选`
- All controls and buttons are at least 44px tall.
- Closing the sheet without applying does not mutate the live list state.

### Archive Detail

Use a full-page detail route rather than a drawer because the content combines long form snapshots, processing fields, notes, tags, history, and export actions.

- Route: `/approval/archive/:sourceType/:id`.
- Desktop layout: `q-page padding`, max content width `1184px`, two columns.
- Left column order:
  1. `归档信息` summary card
  2. `正式提交内容` snapshot card
  3. `后续处理信息` card
  4. `字段修正历史` card
- Right column order:
  1. `操作` card
  2. `标签/标记` card
  3. `内部备注` card
  4. `处理动态` timeline card
- Mobile layout: single column in this order:
  1. Header
  2. Operation actions
  3. Archive info
  4. Tags/marks
  5. Formal submitted content
  6. Processing information
  7. Internal notes
  8. Field correction history
  9. Timeline

Header contract:
- Back button `aria-label`: `返回归档查询`.
- Title: `归档详情`.
- Show source chip first, status chip second.
- Header actions:
  - `打印` outline button.
  - `导出 PDF` outline button.
  - `导出 Excel` is list-level only; do not put list export in a single-record header.
- Do not expose applicant-facing edit controls; all Phase 19 editing is internal operations metadata or controlled correction.

Archive info fields:
- 编号
- 来源
- 模板 `模板名 v版本`
- 申请人/填写者
- 部门
- 提交/收集时间
- 完成时间
- 当前状态
- 最近更新时间
- Snapshot hint: `正式提交内容按提交时快照展示，模板后续变更不会影响本记录。`

Formal submitted content:
- Render from `schemaSnapshot + effective display data`.
- Use `GridFormRenderer mode="print"`.
- When controlled correction overlays a field, show the current effective value with a small `已修正` badge and an inline link/button `查看原值`.
- Missing values show `—`, not blank.
- Mobile dynamic-table print rendering must keep the Phase 18 block fallback so rows wrap vertically.

Processing information:
- Processing fields are clearly separated from formal submitted content.
- Section intro copy: `以下信息为内部后续处理字段，不会覆盖申请人或填写者的正式提交内容。`
- Field controls are generated from template processing-field config.
- Supported field types in Phase 19 UI: text, textarea, date, select, multi-select, phone.
- Unsupported processing field types must not be offered: signature, dynamic table, attachment.
- Save button: `保存处理信息`.
- Successful save uses positive Notify: `处理信息已保存`.

### Tags, Marks, And Internal Notes

Tags/marks:
- Recommended quick tags: `待跟进`, `已核对`, `资料不全`, `重点`.
- Free-text tag input label: `添加标签`.
- Existing tags display as `q-chip dense removable` only when user has mark permission; read-only users see non-removable chips.
- `保存标签` commits all tag changes together and appends an audit/timeline event.
- Removing a tag is a normal metadata update, not a destructive delete confirmation.
- Tags are visible in archive list, archive detail, and authorized approval task detail; they are hidden from applicant `我的申请` detail.

Internal notes:
- Entry point: `添加内部备注`.
- Dialog title: `添加内部备注`.
- Textarea label: `备注内容`.
- Max length: 500.
- Confirm button: `保存备注`.
- Empty/whitespace-only note disables confirm.
- Notes preserve line breaks and render under `内部备注` plus in the timeline as `内部备注`.
- Notes never alter formal submitted content.

### Controlled Edit

Controlled correction is a high-risk internal action with mandatory reason and field-level history.

- Entry point label: `修正提交数据`.
- Visible only with `approval:archive:edit`.
- Dialog title: `修正提交数据`.
- Dialog layout:
  - Summary block: 编号, 来源, 模板, 当前状态.
  - Editable field list generated from formal submitted fields only.
  - Reason textarea label: `修正原因`.
  - Field diff preview: `原值` and `新值`.
- Reason is required and must be non-empty.
- Confirm button: `保存修正`.
- Confirm button stays disabled until at least one field changed and reason is non-empty.
- Warning copy: `保存后系统会保留原始提交值，并追加字段级修改记录。请确认修正原因准确。`
- Successful save closes dialog, refreshes detail, and shows Notify `修正已保存`.
- History card shows field label, original value, corrected value, editor, reason, and time.
- Field history is not included in Excel list export; it remains available in detail.

### Excel And PDF Export

Excel list export:
- Entry point: archive list header `导出 Excel`.
- Export uses current filters and current user's permission scope.
- Button shows loading and is disabled while the export request is in flight.
- If row cap is exceeded, show error copy: `当前筛选结果超过导出上限，请缩小筛选范围后重试。`
- Success downloads `.xlsx`; keep in-app feedback concise: `Excel 导出已开始`.
- Export columns must include metadata, status, department/person, tags/marks, processing fields, and flattened dynamic form fields.
- Do not include full field-level edit history in the list export.

Single-record print/PDF:
- Use existing `#print-area`, `GridFormRenderer mode="print"`, `html2canvas + jsPDF`.
- Default print/PDF emphasizes formal submitted content.
- If an internal processing section is included, it must be visually separated under heading `内部后续处理信息`.
- PDF failure copy: `PDF 导出失败，请重试。`
- Print action uses browser print; no app state change.

### Basic Archive Statistics

Location:
- Add a `统计` tab or section within `归档查询`, not a separate marketing-style dashboard.
- Visible only with archive stats permission, e.g. `approval:archive:stats`.

Layout:
- Desktop: compact filter bar at top, then chart/table grid.
- Mobile: filters in a bottom sheet or stacked controls; charts and tables stack vertically.
- Use existing `FormStatsPanel` style: table plus bar chart.

Stats filters:
- Source type: `全部 / 审批申请 / 公开收集`.
- Date period: `本月 / 近三个月 / 自定义`.
- Optional template and department filters.

Required datasets:
- 按模板统计
- 按状态统计
- 按部门统计
- 按月份统计

Chart contract:
- Use bar charts for template, department, and month counts.
- Use a table alternative next to or below every chart.
- Y-axis starts at zero and uses whole-number ticks.
- Series colors:
  - Total/archive primary count: `#4F46E5`.
  - Collection count or approved count: `#16A34A`.
  - Rejected count: `#DC2626`.
- Each chart canvas has `role="img"` and an `aria-label` describing the aggregation.

### In-App Notifications

Header badge:
- Add a notification icon button in `MainLayout.vue`.
- Unread count loads after login and refreshes on page focus and fixed interval polling.
- Badge displays only when unread count > 0.

Notification menu/list:
- Desktop: `q-menu` anchored to the header icon, width 360px.
- Mobile: route or full-screen dialog `站内通知`; do not crowd the toolbar menu.
- Row order:
  1. unread dot or read state
  2. title
  3. summary
  4. created time
- Rows are at least 56px tall and tappable.
- Click behavior:
  - New task notification routes to `/approval/tasks/:id`.
  - Approved/rejected result notification routes to `/approval/applications/:id`.
  - Click marks the notification as read after navigation intent is accepted.

Notification actions:
- `全部标为已读` appears only when unread count > 0.
- Empty state heading: `暂无站内通知`.
- Empty state body: `新的待办和审批结果会显示在这里。`
- Loading uses skeleton rows, not a spinner-only blank panel.

## State Matrix

| State | Visual Contract |
|-------|-----------------|
| Initial archive list loading | Desktop shows filter skeleton + table skeleton. Mobile shows 3 bordered archive card skeletons. |
| Archive list empty | `EmptyState` with icon `inventory_2`, heading `暂无归档记录`, and body from copy contract. |
| Archive list error | Centered bordered card with `归档数据加载失败，请检查网络后重试。` and primary `重新加载`. |
| Archive list data | Rows/cards show source, status, template, person, department, tags, processing summary, and updated time. |
| Filter applied | Query controls retain current values and table/card list reloads without layout jump. |
| Export loading | `导出 Excel` shows loading and disables duplicate clicks. |
| Export over cap | Negative Notify plus inline banner near export button with row-cap copy. |
| Detail loading | Summary skeleton + form snapshot skeleton + processing/notes/history/timeline skeletons. |
| Detail error | Bordered card with `归档详情加载失败，请检查网络后重试。` and `重新加载`. |
| Detail read-only user | Metadata, formal content, tags, processing info, notes, and history are visible as permitted; edit/save controls hidden. |
| Tags editing | Recommended chips and free-text input visible; `保存标签` disabled until changes exist. |
| Note dialog open | Single textarea with counter, confirm disabled until non-empty. |
| Controlled edit dialog open | Summary, editable fields, reason textarea, and diff preview visible. |
| Controlled edit invalid | Confirm disabled if no changed field or no reason. |
| Controlled edit submitting | Confirm button loading; dialog cannot double-submit. |

## Accessibility And Interaction Rules

- All icon-only buttons require `aria-label` or `q-tooltip`: back, refresh, filter trigger, date picker, notification, close, print, export, row menu.
- Keyboard tab order follows visual order: header actions, filters, table/card actions, detail actions, dialogs, notifications.
- Focus ring uses existing `--oa-focus-ring`; do not remove Quasar focus outlines.
- Mobile touch targets are at least 44px high for all primary actions, filter controls, notification rows, and card actions.
- Entire mobile archive cards use pointer cursor and visible hover/tap feedback without layout shift.
- Status, source type, unread state, and changed-field state are always indicated with text, not color alone.
- Sticky/mobile actions must not overlap content; detail container reserves bottom padding.
- Notes, comments, edit reasons, tag names, and long field values use `overflow-wrap: anywhere`.
- Dynamic table snapshot content must remain readable at 375px with no horizontal page overflow.
- Dialog textarea labels remain visible and counters are available for note/reason fields.
- Loading states reserve layout space and avoid content jumping.
- Chart data is also available as a `q-table`; every chart has an `aria-label`.
- Notification polling must not steal focus or interrupt active form entry.
- Motion stays restrained: 150-200ms hover/fade transitions, no decorative animation.
