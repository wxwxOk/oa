<action>
Create `frontend/src/pages/VisitPage.vue`.

- Load `useVisitStore`, `useAuthStore`, and `useResponsive`.
- On mount, fetch filter options and the first list page.
- Header copy: `到访管理`; create CTA: `新建到访记录` guarded by `visit:create`.
- Desktop filters include keyword, channelPartner, consultant, receptionist, receptionStatus, consultationStatus, statusCategory, dateFrom and dateTo, plus `查询` and `重置筛选` actions.
- Mobile filters use a bottom `q-dialog` sheet with draft filters; live filters update only on `应用筛选`.
- Desktop list uses `QTable` with server-side pagination and `:rows-per-page-options="[10, 20, 50]"`.
- Table scan columns are name, channelPartner, consultant, receptionist, receptionDate, receptionStatus, consultationStatus, statusCategory, updatedAt and actions.
- Mobile list uses cards with class `visit-card`, showing name, status chips, channel/person fields, receptionDate and statusCategory.
- Empty state uses `EmptyState` with `暂无到访记录`; create CTA appears only when `auth.hasPerm('visit:create')`.
</action>

- `frontend/src/pages/VisitPage.vue` contains all filter keys: `keyword`, `channelPartner`, `consultant`, `receptionist`, `receptionStatus`, `consultationStatus`, `statusCategory`, `dateFrom`, `dateTo`.

<threat_model>
- Large Vue pages can become hard to maintain; keep field-heavy form code in `VisitFormDialog`.
- Frontend permission hiding is not security; do not remove backend guards or rely on page-only checks.
- QTable pagination emits Quasar-specific payloads; map page and rowsPerPage carefully to store `page` and `size`.
- Date fields must stay date-only and must not display raw ISO timestamps.
- Do not add fallback dictionaries for statuses; options come from `/visits/filter-options`.
</threat_model>
