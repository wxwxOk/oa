<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser->reimbursement API | Authenticated clients submit reimbursement filters, draft payloads, submit actions and attachments. |
| route body->Prisma | Only explicit business fields may become Prisma writes; actor/applicant fields come from JWT. |
| file upload->filesystem | Uploaded file metadata and names are untrusted and must be rewritten/validated before disk writes. |
| seed permissions->route guards | Reimbursement capabilities are granted only by role permissions and checked again by object-level service guards. |

| T-24-TAMPER | T/E | write schemas | mitigate | Strict TypeBox schemas and explicit field picking; applicant from JWT only. |
| T-24-IDOR | I/E | detail/list/attachment | mitigate | Contract tests require reusable object-authorization helpers for every object read/write. |
| T-24-FILE-PATH | T/E | attachment storage | mitigate | Generated names, relative DB paths and traversal rejection contracts. |
| T-24-FILE-DOS | D | attachment upload | mitigate | 10MB per file and 20 files per application contracts. |
| T-24-STATE | T/R | submit flow | mitigate | Enum states, explicit transition helper and append-only submit action. |
