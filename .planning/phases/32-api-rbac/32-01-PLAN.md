## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser->channel-push API | CHANNEL_PARTNER clients submit pushes, attachments, edits and cancellations; recipient/admin clients read; partners must not access employee endpoints. |
| browser->channel-partner admin API | Authenticated administrators open partner accounts, bind recipients and toggle status; partners must never reach these routes. |
| route body->Prisma | Only explicit business fields may become Prisma writes; `channelPartnerId` and `recipientUserId` always come from JWT/profile, never request body. |
| file upload->filesystem | Uploaded file metadata and names are untrusted — rewritten via `getSafeChannelPushStoredName`, validated against MIME/size/count and rejected on traversal via `resolveSafeChannelPushPath`. |
| seed permissions->route guards | Channel-push capabilities are granted only via the CHANNEL_PARTNER role (or explicit recipient grant in Phase 35) and re-checked by object-level guards on every mutation. |
