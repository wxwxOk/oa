  <action>
    Add a Prisma notification model that can back the header badge and dropdown without accepting any client-supplied user scope.

    Implement:
    - `enum UserNotificationType` with `CHANNEL_PUSH_PENDING_REVIEW` and `CHANNEL_PUSH_REVIEWED`
    - `model UserNotification` with `userId`, `type`, `title`, `summary`, `targetRoute`, `sourceType`, `sourceId`, `readAt`, `createdAt`, user relation, and indexes for user/date/unread lookup
    - a `notifications` backref on `User`
    - migration SQL that matches the Prisma schema

    Create `backend/src/modules/channel-push/channel-push-notification.service.ts` with:
    - `notifyChannelPushPendingReview(tx, input)`
    - `notifyChannelPushReviewed(tx, input)`
    - `listNotifications(actor, query)`
    - `getUnreadNotificationCount(actor)`
    - `markNotificationRead(actor, id)`
    - `markAllNotificationsRead(actor)`
    - `serializeNotificationRow(row)`

    Required content rules:
    - Pending-review notifications use title `渠道推送待审核` and target route `/review/channel-push/{pushId}`
    - Reviewed notifications use title `我的推送已审核` and target route `/channel-push/{pushId}`
    - List rows return newest first and expose `readAt` / `createdAt` as ISO strings
    - Count helpers scope by `userId = actor.id`
    - Read helpers update only the current user

    Create `backend/src/modules/channel-push/channel-push-notification.route.ts` with:
    - `GET /notifications`
    - `GET /notifications/unread-count`
    - `POST /notifications/:id/read`
    - `POST /notifications/read-all`
    - `authGuard()` on every route

    Add focused tests that pin:
    - schema/enum names
    - route prefix and signatures
    - user-scoped read/count behavior
    - `userId` never coming from the request body
    - no route leak to external channels or admin-only scopes
  </action>

    - In `decideReviewChannelPush`, create the `CHANNEL_PUSH_REVIEWED` row for the partner inside the same transaction that updates status and appends the APPROVE or REJECT action.

    - change read endpoints in `channel-push-review.route.ts` to `authGuard()` while keeping mutation endpoints on `authGuard('channelPush:review')`
