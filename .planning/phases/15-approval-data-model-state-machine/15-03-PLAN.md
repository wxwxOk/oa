Implementation details:

1. Add helper `getProcessNodes(snapshot)` that validates `snapshot.nodes` is a non-empty array when submitting and sorts by `order`.
2. Add helper `createActionAndTimeline(tx, input)` that creates one `approvalAction` row and one `approvalTimelineEvent` row with matching application/task/actor/node/type/comment/payload fields.
3. `createDraftApplication(input)` creates `prisma.approvalApplication.create` with:
   - `applicationNo`
   - `status: 'DRAFT'`
   - `formData`
   - `schemaSnapshot`
   - `processSnapshot: input.processSnapshot as Prisma.InputJsonValue`
   - `templateId`, `templateName`, `templateVersion`
   - `processId: input.processSnapshot.processId ?? null`
   - `processName: input.processSnapshot.processName ?? null`
   - `applicantId`, `applicantName`, `applicantDepartmentId`, `applicantDepartmentName`
4. `submitApplication(applicationId, actor)` runs `prisma.$transaction(async (tx) => { ... })`:
   - load application by id including `tasks`
   - if missing throw `notFound('审批申请不存在')`
   - call `assertApplicationTransition(application.status, 'SUBMITTED')`
   - create `SUBMIT` action/timeline with title `提交申请`
   - resolve first node from application `processSnapshot`
   - create first `ApprovalTask` with `nodeOrder`, `nodeName`, `status: 'PENDING'`, `assigneeId`, `assigneeName`, `approverSourceSnapshot` containing source type/user/role/label
   - create `ASSIGN` action/timeline with title `分配审批任务`
   - call `assertApplicationTransition('SUBMITTED', 'APPROVING')`
   - update application to `APPROVING`, `submittedAt: new Date()`, `currentNodeOrder`, `currentNodeName`
   - return updated application with `tasks`
5. `approveTask(taskId, actor, comment)` runs a transaction:
   - load task with application and application.tasks
   - throw `notFound('审批任务不存在')` if missing
   - call `assertPendingTask(task.status)`
   - if `actor.id !== task.assigneeId`, throw `new BizError('无权处理该审批任务', 403, 'APPROVAL_TASK_FORBIDDEN')`
   - if `task.application.status !== 'APPROVING'`, call `assertApplicationTransition(task.application.status, 'APPROVED')` to throw the centralized error
   - update current task status `APPROVED`, `handledAt`, `comment`
   - append `APPROVE` action/timeline with title `审批通过`
   - find next node by `order > task.nodeOrder`
   - if next node exists: create next `PENDING` task and append `ASSIGN`, update application `currentNodeOrder/currentNodeName`
   - if no next node: call `assertApplicationTransition('APPROVING', 'APPROVED')`, update application `status: 'APPROVED'`, `completedAt`, `currentNodeOrder: null`, `currentNodeName: null`
6. `rejectTask(taskId, actor, comment)`:
   - require pending task and application `APPROVING`
   - if `actor.id !== task.assigneeId`, throw `new BizError('无权处理该审批任务', 403, 'APPROVAL_TASK_FORBIDDEN')`
   - update current task to `REJECTED`
   - `updateMany` all other pending tasks for application to `CANCELED`
   - append `REJECT` action/timeline with title `审批驳回`
   - call `assertApplicationTransition('APPROVING', 'REJECTED')`
   - update application to `REJECTED`, `completedAt`, clear current node
7. `cancelApplication(applicationId, actor, comment)`:
   - load application
   - throw not found if missing
   - if `actor.id !== application.applicantId`, throw `new BizError('无权撤销该审批申请', 403, 'APPROVAL_CANCEL_FORBIDDEN')`
   - call `assertApplicationTransition(application.status, 'CANCELED')`
   - update all pending tasks to `CANCELED`
   - append `CANCEL` action/timeline with title `撤销申请`
   - update application to `CANCELED`, `completedAt`, clear current node
8. `appendApplicationEvent(input)`:
   - allow only `COMMENT`, `MARK`, `EDIT`; otherwise throw `new BizError('仅允许追加备注、标记或编辑事件', 400, 'INVALID_APPROVAL_EVENT_TYPE')`
   - verify application exists; if missing throw `notFound('审批申请不存在')`
   - create paired action/timeline rows
   - do not update `ApprovalApplication.formData`

Return values should include `tasks` where service tests need task assertions.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Service caller -> approval transaction | Caller requests workflow mutations that must stay atomic |
| Runtime application -> historical snapshots | Live template/process/user/department changes must not rewrite historical application meaning |
| Actor input -> audit event | Actor identity/comment/payload must be recorded without mutating original form data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-01 | Tampering | application.service status changes | mitigate | Call `assertApplicationTransition` before terminal and non-terminal application state updates |
| T-15-02 | Tampering | submit/approve/reject/cancel transactions | mitigate | Wrap application status, task state, action, and timeline writes in `prisma.$transaction` |
| T-15-03 | Tampering | application snapshots | mitigate | `createDraftApplication` persists schema/process/template/applicant/department snapshots at creation |
| T-15-04 | Elevation of Privilege | task handling and cancellation | mitigate | `approveTask` and `rejectTask` must require `actor.id === task.assigneeId`; `cancelApplication` must require `actor.id === application.applicantId`; negative service tests must prove unauthorized actors leave task/application state unchanged |
| T-15-05 | Repudiation | event append | mitigate | Paired append-only `ApprovalAction` and `ApprovalTimelineEvent` rows; `appendApplicationEvent` does not mutate `formData` |
</threat_model>
