<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Department admin input -> department table | Admin-selected approver becomes future approval assignee source |
| Seed data -> authorization decisions | Permission seed controls access to process configuration, template binding, and future approval actions |
| Normal user -> approval management routes | Users without approval permissions must not see or call admin approval controls |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T16-04 | Elevation of Privilege | department default approver API | mitigate | Create/update accepts only active users; option endpoint returns active users and is guarded by `department:update` |
| T16-06 | Elevation of Privilege | `backend/prisma/seed.ts` | mitigate | Seed all Phase 16 permission codes, assign all to ADMIN, and assign only application create/own to EMPLOYEE |
| T16-06 | Spoofing | department approver options | mitigate | Use existing JWT `authGuard('department:update')`; no public or unauthenticated approver metadata endpoint |
</threat_model>
