<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser UI -> approval process API | Admin-entered nodes become backend process definitions |
| Router/nav -> normal user session | Frontend route visibility must reflect RBAC permissions |
| Mobile touch UI -> destructive operations | Dense mobile controls can trigger disable/delete mistakes if labels/confirmations are unclear |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T16-02 | Denial of Service | `ApprovalProcessPage.vue` | mitigate | UI requires at least one node and uses backend validate/save errors for unassignable processes |
| T16-03 | Elevation of Privilege | role approver selector | mitigate | UI labels role source but backend remains source of truth for exactly-one-active-user validation |
| T16-04 | Elevation of Privilege | department-manager source selector | mitigate | UI does not choose arbitrary users for department-manager; backend resolves from department hierarchy |
| T16-06 | Elevation of Privilege | router/navigation/buttons | mitigate | Route `meta.perm`, menu `perm`, and `v-perm` controls use `approval:process:*` codes |
</threat_model>
