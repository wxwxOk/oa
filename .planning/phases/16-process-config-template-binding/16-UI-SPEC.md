## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge gaps, inline helper text spacing |
| sm | 8px | Compact form gaps, node-row internal gaps, card action gaps |
| md | 16px | Default page padding, dialog sections, process editor node padding |
| lg | 24px | Toolbar-to-content spacing, grouped form section spacing |
| xl | 32px | Wide dialog internal grouping when two-column controls are used |
| 2xl | 48px | Empty, loading, and error state vertical padding |
| 3xl | 64px | Not used for new Phase 16 admin views |

Exceptions:
- `44px` minimum touch target for mobile primary buttons, icon buttons, and form controls.
- `1px` borders for Quasar `flat bordered` cards, tables, panels, and node rows.
- No new arbitrary spacing values beyond existing Quasar classes unless inherited from existing components.

## Typography

Use exactly two weights: regular `400` and semibold `600`.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Caption / helper | 12px | 400 | 1.5 |
| Body / table row | 14px | 400 | 1.5 |
| Label / section label | 14px | 600 | 1.5 |
| Page / dialog heading | 20px | 600 | 1.2 |

Rules:
- Page titles use existing `.text-h6` override: 20px, 600, 1.2.
- Process node names, template names, and department names use 14px or 16px Quasar subtitle styles, never hero-scale text.
- Error and helper copy stays at 12px or 14px and must wrap without horizontal overflow on 375px screens.

## Layout And Component Contract

### Navigation

- Add a desktop/mobile-visible navigation group named `审批管理` with material icon `approval` or `fact_check`.
- Phase 16 includes one route entry: `流程配置`, icon `rule`, route guarded by `approval:process:list`.
- Keep `模板管理` inside the existing `收集统计表` group; template binding is an extension of template management, not a separate page.

### Process Config Page

Use the existing admin list pattern from `TemplatePage.vue` and `UserPage.vue`.

Desktop layout:
- Container: `q-page padding`.
- Toolbar: `row items-center q-mb-md`.
- Left title: `流程配置`.
- Right primary CTA: `q-btn color="primary" icon="add" label="新建流程"`, gated by `approval:process:create`.
- Filters: `q-btn-toggle` for `全部 / 启用 / 停用`; optional search input placeholder `搜索流程名称`.
- Data view: `q-table flat bordered dense`, row-key `id`, pagination `[10, 20, 50]`.

Desktop table columns:

| Column | Label | Width | Content |
|--------|-------|-------|---------|
| name | 流程名称 | auto | name + optional description caption |
| status | 状态 | 80px | enabled/disabled badge |
| nodes | 节点 | 140px | `{N} 个节点` + first two node names as caption when space allows |
| updatedAt | 更新时间 | 160px | `YYYY-MM-DD HH:mm` |
| actions | 操作 | 180px | validate, edit, enable/disable, delete |

Mobile layout:
- Header row title `流程配置` + `筛选` button when filters exceed one row.
- Cards use `q-card flat bordered` with 8px radius or less.
- Card content: process name, status badge, `{N} 个节点`, updated time, and right-aligned icon actions.
- Mobile create/edit dialog is maximized with `slide-up` / `slide-down`.

### Process Editor Dialog

Use a practical ordered node form, not a BPMN canvas.

Dialog:
- Desktop width: 760px min, max-width `calc(100vw - 32px)`.
- Mobile: maximized.
- Title: `新建审批流程` or `编辑审批流程`.
- Content uses `q-form greedy` and `q-card-section class="q-gutter-md"`.

Top fields:
- `流程名称` `q-input outlined`, required, max 50 chars.
- `描述` `q-input outlined type="textarea" autogrow`, optional.
- `启用` `q-toggle`, default on for new processes.

Node list:
- Section heading: `审批节点`.
- Empty node list is invalid; show inline warning `至少添加 1 个审批节点`.
- Each node row is a bordered block with 8px radius or less, `padding: 16px`, `gap: 8px`.
- Node header: `第 {N} 步` caption + move up/down icon buttons + delete icon button.
- Fields per node:
  - `节点名称` `q-input outlined dense`, required.
  - `审批人来源` `q-select outlined dense`, options `固定用户 / 角色 / 提交人部门负责人`.
  - `固定用户` `q-select outlined dense use-input`, visible only for fixed user, active users only.
  - `角色` `q-select outlined dense`, visible only for role source.
  - `必需动作` read-only chip group: `通过` and `驳回`.
- Add node action: `q-btn flat color="primary" icon="add" label="添加节点"`.
- Reordering uses up/down icon buttons, not a drag canvas.

Validation interaction:
- `保存流程` runs form validation and process-structure validation.
- `校验流程` can be a secondary flat button if implemented; it must report the same validation errors as save.
- Errors appear next to the field or node row causing the issue and also produce `Notify negative` for server-side validation failures.
- Save buttons use loading state and are disabled while submitting.

### Template List And Designer Binding

Template list:
- Add a `用途` column next to existing `状态`.
- Show two badges: status (`草稿 / 已发布 / 已下线`) and purpose (`仅收集 / 需审批`).
- Add purpose filter `全部用途 / 仅收集 / 需审批` beside the existing status filter.
- Hide the share icon for `APPROVAL_REQUIRED` templates. If an unavailable action is shown for discoverability, it must be disabled with tooltip `需审批模板不生成公开分享链接`.
- Keep submission-list action only for collection-only/public collection records in this phase.

Form designer:
- Add template-level controls in the existing top toolbar area, after `要求填写者提供身份信息`.
- `用途` control: dense outlined `q-select`, width 140px, options `仅收集` and `需审批`.
- `审批流程` control: dense outlined `q-select`, width 220px, shown only when purpose is `需审批`; options include only enabled flows, with invalid/empty state copy from this spec.
- `保存设计` saves schema, identity requirement, purpose, and process binding through the existing template store update flow.
- Approval mode and process binding changes do not show a schema-version info notification. Schema edits continue to show `模板已更新至 v{N}`.

Mode switching safeguards:
- Switching a published collection-only template with active public links to `需审批` opens a persistent confirm dialog before save.
- Confirm dialog must explicitly state that public collection entrypoints will be disconnected.
- No silent mode change is allowed.

Publish behavior:
- Collection-only publish keeps the existing copy about share links.
- Approval-required publish copy says the template will be used for internal approval submissions and requires a valid enabled process.
- Publishing an approval-required template without a process shows an inline error at the process selector: `请选择启用且有效的审批流程`.

### Department Default Approver UI

Extend `DepartmentPage.vue`; do not create a separate approver page.

Tree display:
- Each department node shows department name plus helper text or chip:
  - With approver: `负责人：{realName}`.
  - Without approver: `未设置负责人`.
- Use text, not color alone, to communicate missing approver.

Create/edit dialog:
- Add `负责人/默认审批人` `q-select outlined clearable`.
- Options include active users; label format `{realName}（{username}）`.
- The field is optional because parent fallback is allowed.
- Save button remains `保存部门`.

### Required Field Validation

- Keep the existing designer `必填` toggle in `PropertyEditor.vue`; this remains the only Phase 16 UI for field requiredness.
- Required fields show a red `*` beside the field label in fill mode.
- PC and mobile fill pages must show the same field-level messages for the same schema.
- Required validation messages:
  - Text / textarea: `此项为必填`.
  - Date: `请选择日期`.
  - Phone: `请输入有效手机号`.
  - Radio: `请选择一项`.
  - Checkbox: `请至少选择一项`.
  - Signature: `请签名`.
- Dynamic-table column-level required UI is out of scope and must not be added in Phase 16.

## State Matrix

| State | Visual Contract |
|-------|-----------------|
| Initial loading | Desktop: `q-skeleton` table header + 5 rows. Mobile: 3 bordered card skeletons. |
| Filter/page loading | `q-table :loading="true"` and controls remain visible. |
| Empty process list | `EmptyState` icon `rule`, heading `暂无审批流程`, body from copy contract, CTA `新建流程` when permitted. |
| Network error | Centered message `流程配置加载失败，请检查网络后重试。` + `重新加载` primary button. |
| Process list data | Desktop table or mobile cards; status and node count visible without opening the editor. |
| Editor create | Empty form with one default node row only if implementation can prefill valid defaults; otherwise no-node inline error appears on save. |
| Editor edit | Existing process fields and ordered nodes loaded; node order visually matches execution order. |
| Validation failure | Inline node/field errors persist until corrected; server validation also shows `Notify negative`. |
| Save success | `Notify positive` with `流程已保存`, dialog closes, list refreshes. |
| Delete blocked | `Notify negative` with backend reason; keep row in list. |
| Template approval mode missing process | Process selector error visible before publish/save; publish action does not proceed. |
| Public collection disconnect confirm | Persistent `Dialog.create`; cancel leaves mode unchanged. |
| Department approver missing | Tree row shows `未设置负责人`; not a blocking error in department management. |

## Accessibility And Interaction Rules

- All icon-only buttons must have `aria-label` or `q-tooltip`: edit process, validate process, move node up/down, delete node, share disabled reason.
- Keyboard tab order follows visual order: toolbar filters, table actions, dialog fields, node rows, dialog actions.
- Focus ring uses existing global `--oa-focus-ring`; do not remove Quasar focus outlines.
- Mobile dialogs are maximized for process editing and department editing; no horizontal scrolling at 375px.
- Node rows must preserve stable height during hover/focus; hover states use background/border color only.
- Buttons in async operations set `loading` and prevent duplicate submit.
- Status and purpose badges include visible text; color is never the only state indicator.
- Touch targets on mobile are at least 44px high, including node action buttons and sticky/floating CTAs if added.
