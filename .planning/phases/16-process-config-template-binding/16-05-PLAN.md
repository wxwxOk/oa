6. Optional fields may be absent.

Implementation target:

   - `approvalProcessId`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public browser/API -> public submission route | Untrusted unauthenticated data attempts to create `Submission` rows |
| Template admin -> public collection behavior | Admin mode changes can break existing public links if not explicit |
| Template publish -> process runtime | Publishing can expose an approval template whose process cannot assign tasks |
| Template edit route -> approval binding | Existing form edit permission is broader than approval template binding permission |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T16-01 | Tampering | `template.route.ts`, `public.route.ts` | mitigate | Default mode remains `COLLECTION_ONLY`; published shared templates need `disconnectPublicCollection`; share creation and public routes block `APPROVAL_REQUIRED` |
| T16-02 | Denial of Service | template publish | mitigate | Publish approval-required templates only after `validateProcessDefinition(approvalProcessId)` succeeds |
| T16-05 | Tampering | public submission route | mitigate | Reuse `validateFormDataRequiredFields` before `Submission` creation; server controls `schemaVersion` |
| T16-06 | Elevation of Privilege | template update route | mitigate | Binding changes require `approval:template:bind` or ADMIN role, in addition to existing form template edit route guard |
</threat_model>
