Create `backend/src/modules/approval/process-config.service.ts`.

Decision trace: implements D-06, D-09, D-10, D-13, D-14, D-15, D-16, D-17, and D-18 by validating process definitions, resolving every approver source to concrete assignees for future snapshots, requiring exactly one active role user, using parent department fallback, avoiding self-approval, and failing before partial application/task creation in later callers.

Implementation requirements:
1. Import Prisma types as needed, `prisma` from `../../plugins/prisma`, `BizError`/`notFound`, and `ApprovalProcessSnapshot` from `./application.service`.
2. Export `ProcessNodeInput`, `validateProcessStructure`, `validateProcessDefinition`, `resolveProcessSnapshot`, and `resolveDepartmentApprover`.
3. Add internal `loadProcessWithNodes(processId, client = prisma)` that includes ordered nodes, `approverUser`, and `approverRole`; it must accept a Prisma transaction client so route create/update can validate uncommitted proposed rows.
4. `validateProcessStructure(processId, client = prisma)` is structural validation for save/update. It must not throw only because `isActive` is false. It must throw:
   - `notFound('审批流程不存在')` if missing.
   - `BizError('至少添加 1 个审批节点', 400, 'APPROVAL_PROCESS_NO_NODES')` for zero nodes.
   - `BizError('审批节点顺序必须从 1 开始且不能重复', 400, 'APPROVAL_PROCESS_NODE_ORDER_INVALID')` for non-positive, duplicate, or non-contiguous order.
   - `BizError('审批节点名称不能为空', 400, 'APPROVAL_PROCESS_NODE_NAME_REQUIRED')` for blank names.
   - `BizError('固定用户审批节点必须选择启用用户', 400, 'APPROVER_USER_INVALID')` when `USER` node lacks an active user.
   - `BizError('角色审批人必须恰好 1 个启用用户', 400, 'APPROVER_ROLE_USER_COUNT_INVALID')` when `ROLE` node resolves to zero or multiple active users.
   - `BizError('部门负责人节点不能配置固定用户或角色', 400, 'DEPARTMENT_MANAGER_NODE_INVALID')` when `DEPARTMENT_MANAGER` has `approverUserId` or `approverRoleId`.
5. `validateProcessDefinition(processId, client = prisma)` is active-runtime validation for template publish, template binding validation, `resolveProcessSnapshot`, and future submission/runtime use. It must call `validateProcessStructure(processId, client)` first, then throw `BizError('审批流程已停用', 400, 'APPROVAL_PROCESS_INACTIVE')` when `isActive` is false.
6. Role resolution must count active users through `UserRole` where `user.status === 'ACTIVE'` and must not implement first-wins/all-must-approve semantics per D-15.
7. `resolveDepartmentApprover(departmentId, applicantId)` must:
   - require a non-null applicant department id.
   - walk current department, then parents through `parentId`.
   - load `defaultApprover` and require `status === 'ACTIVE'`.
   - skip any approver whose id equals `applicantId` and continue upward.
   - throw `BizError('不能解析提交人部门负责人，请维护部门负责人', 400, 'DEPARTMENT_MANAGER_NOT_RESOLVED')` when no valid non-self approver exists.
8. `resolveProcessSnapshot(processId, applicantId)` must:
   - call `validateProcessDefinition(processId)`.
   - load applicant with current department.
   - resolve every node to concrete `assigneeId` and `assigneeName`.
   - return `{ processId, processName, nodes }` sorted by `order`.
   - set `approverSourceLabel` to `固定用户: {realName}`, `角色: {role.name}`, or `提交人部门负责人`.

Do not create approval applications or tasks in this service. It only validates definitions and resolves snapshots for later transactional application submission.

Decision trace: implements D-07, D-08, D-11, and D-12 by creating a practical process configuration API over `ApprovalProcess`/`ApprovalProcessNode`, using ordered node forms instead of BPMN/canvas behavior, blocking disable/delete while published approval templates reference a process, and keeping required actions fixed to pass/reject.

```ts
export const approvalProcessModule = new Elysia({ prefix: '/approval/processes' })
```

Register under authenticated `/api/v1` modules in `backend/src/index.ts` with `.use(approvalProcessModule)`, not under public routes.

Endpoints:
1. `GET /approval/processes`
   - guard `approval:process:list`
   - query: optional `isActive`, `keyword`, `page`, `size`
   - return `{ rows, total, page, size }`
   - include `_count.nodes` or a serialized `nodes` summary with read-only `requiredActions: ['APPROVE', 'REJECT']`
2. `GET /approval/processes/:id`
   - guard `approval:process:list`
   - include ordered nodes with `requiredActions: ['APPROVE', 'REJECT']`
3. `POST /approval/processes`
   - guard `approval:process:create`
   - body `{ name, description?, isActive?, nodes }`
   - create process and replace nodes in one Prisma transaction
   - default `isActive` to true
   - call `validateProcessStructure(created.id, tx)` inside that same transaction before the transaction callback returns; if validation throws, no process or node rows may commit
4. `PUT /approval/processes/:id`
   - guard `approval:process:update`
   - update `name`, `description`, `isActive`, and replace nodes transactionally
   - call `validateProcessStructure(id, tx)` inside that same transaction before the transaction callback returns; if validation throws, the previous process and node rows must remain unchanged
5. `PATCH /approval/processes/:id/status`
   - guard `approval:process:update`
   - body `{ isActive: boolean }`
   - when setting `false`, block if any published `APPROVAL_REQUIRED` `FormTemplate` references this process; throw `BizError('已发布需审批模板正在引用该流程，不能停用', 400, 'APPROVAL_PROCESS_BOUND_BY_PUBLISHED_TEMPLATE')`
   - when setting `true`, call `validateProcessStructure(id)` before enabling so invalid disabled drafts cannot become active
6. `DELETE /approval/processes/:id`
   - guard `approval:process:delete`
   - same published-template binding block as status disable
   - delete process only when not blocked
7. `POST /approval/processes/:id/validate`
   - guard `approval:process:list`
   - call `validateProcessStructure(id)` and return `{ ok: true }`; this endpoint is an admin structure check and must not reject solely because the process is inactive

TypeBox body for node input must use exact enum literals `USER`, `ROLE`, `DEPARTMENT_MANAGER`; `approverUserId` and `approverRoleId` are optional nullable numbers. Node replacement must normalize `order` from the submitted ordered array or reject non-positive/duplicate order consistently with the service.

Extend the Wave 0 process config test file with these exact rollback tests:
1. `failed process create rolls back invalid process and nodes` — attempt to create a process with invalid proposed node data through the create path, assert the request rejects, and assert both `approvalProcess.count()` and `approvalProcessNode.count()` are unchanged.
2. `failed process update leaves previous process and nodes unchanged` — create a valid process, attempt to update it with invalid proposed nodes, assert the update rejects, and assert the original process fields and ordered node rows are still present.
3. `inactive structurally valid process can be saved but not used at runtime` — save or update an inactive process with valid nodes, assert structural validation succeeds, then assert active-runtime validation rejects with `APPROVAL_PROCESS_INACTIVE`.

Do not add BPMN, visual canvas, conditional branch, parallel, countersign, delegation, transfer, timeout, or multi-user role approval behavior.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin request -> process definition tables | Untrusted admin input defines future approval task owners |
| Process definition -> runtime process snapshot | Live configurable nodes become executable approval assignment data |
| Role/department/user data -> assignee resolution | Organization metadata controls who can approve |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T16-02 | Denial of Service | `validateProcessStructure` / `validateProcessDefinition` | mitigate | Structural validation rejects zero nodes, invalid order, blank names, disabled/missing fixed users, invalid role memberships, and malformed department-manager nodes inside save/update transactions; active-runtime validation additionally rejects inactive processes for template publish, binding validation, and snapshot resolution |
| T16-03 | Elevation of Privilege | role approver source | mitigate | Role nodes must resolve to exactly one active user; zero or multiple active users throw `APPROVER_ROLE_USER_COUNT_INVALID` |
| T16-04 | Elevation of Privilege | department-manager approver source | mitigate | Parent lookup skips applicant self-approval and throws before snapshot resolution succeeds when no valid non-self approver exists |
| T16-06 | Elevation of Privilege | process route access | mitigate | Every endpoint uses `authGuard` with `approval:process:*` permission codes and route is registered only under authenticated `/api/v1` |
</threat_model>
