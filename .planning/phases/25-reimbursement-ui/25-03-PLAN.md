<action>
Create `frontend/src/components/reimbursement/ReimbursementAttachmentPanel.vue`.

Use these props:
- `applicationId?: number | null`
- `attachments: ReimbursementAttachment[]`
- `editable?: boolean`

Use these emitted events:
- `uploaded`
- `deleted`

Implementation requirements:
- Import `useReimbursementStore`, `useAuthStore`, `ALLOWED_REIMBURSEMENT_MIME_TYPES`, `MAX_REIMBURSEMENT_FILE_SIZE`, `MAX_REIMBURSEMENT_ATTACHMENTS`, `formatFileSize`, and `formatReimbursementDate`.
- Render a section title `附件` and a `q-file` with `multiple`, `outlined`, `accept="image/jpeg,image/png,image/webp,application/pdf"`, `:max-file-size="10 * 1024 * 1024"`, and `@rejected` feedback.
- Disable upload when `!applicationId`, when `editable !== true`, when the user lacks `auth.hasPerm('reimbursement:attachment')`, or when `attachments.length >= 20`.
- When `!applicationId`, show the exact hint `先保存草稿后上传附件`.
- On valid file selection, upload selected files sequentially with `store.uploadAttachment(applicationId, file)`; after each successful upload emit `uploaded`; on any failed file show a negative `Notify` mentioning the file name.
- Render attachment rows showing `originalName`, `mimeType`, formatted `size`, formatted `createdAt`, and action buttons.
- Show `预览` only for image MIME types `image/jpeg`, `image/png`, `image/webp`; show `下载` for every attachment.
- `预览` must call `store.previewAttachmentBlob(applicationId, attachment.id)`, then `URL.createObjectURL(blob)`, render a `q-dialog` image preview using the object URL, and call `URL.revokeObjectURL` when the dialog closes and in `onUnmounted`.
- `下载` must call `store.downloadAttachment(applicationId, attachment.id)`, create a blob URL, create a local anchor with `download = attachment.originalName`, click it, then revoke the object URL.
- `删除` is visible only when `editable === true`, `applicationId` exists, and `auth.hasPerm('reimbursement:attachment')`; confirmation copy must include `确认删除附件「${attachment.originalName}」？`; successful delete calls `store.deleteAttachment(applicationId, attachment.id)` and emits `deleted`.
- Do not use `window.open`. Do not embed `/reimbursements/${id}/attachments/${attachmentId}/preview` or `/download` as direct template URLs.
</action>

<action>
Create `frontend/src/pages/ReimbursementFormPage.vue`.

Page behavior:
- Use `q-page padding`, `q-form`, `useRoute`, `useRouter`, `Notify`, `useResponsive`, and `useReimbursementStore`.
- Detect create mode when `route.path === '/reimbursements/new'`; detect edit mode from `Number(route.params.id)` for `/reimbursements/:id/edit`.
- Local form state must include exactly: `title`, `category`, `occurredAt`, `amount`, `reason`, `payeeInfo`, `remark`.
- In edit mode, call `store.fetchDetail(id)` on mount. If loaded detail status is not `DRAFT`, redirect to `/reimbursements/${id}` and do not render editable fields.
- Required fields and validation copy: `title` -> `请输入报销标题`, `category` -> `请输入报销类别`, `occurredAt` -> `请选择发生日期`, `amount` -> `报销金额必须大于 0`, `reason` -> `请输入报销事由`.
- Form controls: `q-input` for `title`, `category`, `amount`, `reason`, `payeeInfo`, `remark`; date-only input or `q-date` popup for `occurredAt` that stores `YYYY-MM-DD`.
- Actions: `返回`, `保存草稿`, `提交申请`. Desktop actions live in card actions; mobile actions use a sticky `.mobile-actions` area with `padding-bottom: env(safe-area-inset-bottom)` and button min-height `44px`.
- `saveDraft()` validates fixed field shape enough for backend create/update, calls `store.createDraft(form)` if no saved ID exists, otherwise `store.updateDraft(id, form)`, shows `草稿已保存`, and if creating replaces the route with `/reimbursements/${draft.id}/edit` so attachment upload has an ID.
- `submitApplication()` validates required fields, creates or updates the draft first, then calls `store.submitDraft(id)`, shows `报销申请已提交，等待部门初审`, and routes to `/reimbursements/${id}`.
- Render `ReimbursementAttachmentPanel` below the fixed fields with `:application-id="savedApplicationId"`, `:attachments="attachments"`, and `:editable="true"`; it must show `先保存草稿后上传附件` before the first save.
- On attachment `uploaded` or `deleted`, reload detail when `savedApplicationId` exists.
- Do not use `GridFormRenderer`, `/approval/applications`, review action copy, export copy, OCR copy, or direct file URLs.
</action>

<threat_model>
- Draft creation and upload are a state boundary: do not enable upload before an application ID exists.
- Attachment preview/download is an auth boundary: all file access must use the store's authenticated blob methods.
- Submitted applications are immutable in Phase 25: non-draft edit routes must redirect to detail.
- Repeated save/submit/upload clicks can duplicate requests; bind buttons to store/page loading states.
- Frontend `reimbursement:attachment` checks are UX only; backend object authorization remains authoritative.
</threat_model>
