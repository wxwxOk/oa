    Create `ChannelPushReviewAttachmentPanel.vue` as a read-only attachment component. It should render the same attachment metadata as `ChannelPushAttachmentPanel.vue`, but only expose image preview and download actions through `store.previewReviewAttachmentBlob` and `store.downloadReviewAttachmentBlob`. It must not render q-file upload, delete buttons, or partner attachment mutation calls.

    Create `ChannelPushReviewDetailPage.vue` with these sections:
    - Header: back button to `/review/channel-push`, title `推送审核详情`, subtitle `studentName · studentPhone`, and `ChannelPushStatusChip`
    - `渠道商提交信息`: channel partner name, student fields, intent fields, original remark, submitted time
    - `重复提示`: if `duplicateHints.length > 0`, render a banner/list showing student name, phone, status chip, and submitted time; otherwise show `暂无重复提示`
    - `附件`: use `ChannelPushReviewAttachmentPanel`
    - `内部字段`: editable fields `计划接待人`, `预期接待日期`, `内部备注` and a `保存内部字段` action
    - `处理状态`: current status, reviewedAt, reviewComment
    - `审核时间线`: oldest-to-newest reviewActions list
    - `审核操作`: approve/reject controls for PENDING details

    Internal field behavior:
    - `计划接待人` uses a searchable q-select that sends `internalScheduledReceiverId`; load options from the existing `/users` API with `{ keyword, page: 1, pageSize: 20, status: 'ACTIVE' }` and show labels as `realName || username`.
    - `预期接待日期` uses q-date with `YYYY-MM-DD` mask.
    - `内部备注` is a textarea with max 1000 chars.
    - `保存内部字段` calls `store.saveReviewInternalFields(detail.id, payload)` and reloads detail on success.

    Review action behavior:
    - `canReview` is true only when `detail.status === 'PENDING'` and `auth.hasPerm('channelPush:review')`.
    - Approve dialog title: `确认通过审核`; textarea label: `审核备注（选填）`; submit calls `store.approveReview(id, { comment })`.
    - Reject dialog title: `确认驳回审核`; textarea label: `驳回意见 *`; submit is disabled until `comment.trim().length > 0`; submit calls `store.rejectReview(id, { comment })`.
    - After save/approve/reject success, reload current detail and refresh both pending and handled list caches with current store filters.
    - Mobile renders a sticky action bar with class `mobile-review-actions`; buttons use `review-action-save`, `review-action-approve`, and `review-action-reject`, all with `min-height: 44px`.

    Add a detail page test that pins copy, the permission-gated action selectors, internal-field labels, duplicate hint section, and review store action calls.
