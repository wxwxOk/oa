  <action>
    Create `backend/src/modules/channel-push/channel-push-review.service.ts` as the reviewer-side data layer for Phase 35.

    Implement these exports:
    - `normalizeReviewListFilters(input)` with `page`, `size`, `channelPartnerKeyword`, `status`, `dateFrom`, `dateTo`
    - `listReviewPendingChannelPushes(actor, query)`
    - `listReviewHandledChannelPushes(actor, query)`
    - `getReviewChannelPush(id, actor)`
    - `saveReviewInternalFields(id, actor, body)`
    - `approveReviewChannelPush(id, actor, body)`
    - `rejectReviewChannelPush(id, actor, body)`
    - `serializeChannelPushReviewRow(push)`
    - `serializeChannelPushReviewDetail(push, duplicateHints)`

    Required behavior:
    - Pending list filters by `recipientUserId = actor.id`, `status = 'PENDING'`, optional `channelPartnerKeyword`, and date range on `submittedAt`.
    - Handled history filters by `recipientUserId = actor.id`, `status IN ('APPROVED', 'REJECTED')`, optional `channelPartnerKeyword`, and date range on `reviewedAt` or `submittedAt` as defined by the row serializer.
    - Detail loads attachments and review actions, derives `reviewedAt` / `reviewComment` from the latest APPROVE or REJECT action, and computes `duplicateHints` through `findChannelPushDuplicates`.
    - Internal-field updates persist `internalScheduledReceiverId`, `internalScheduledDate`, and `internalNote` on `ChannelPush` only; they do not alter partner-submitted write fields.
    - Approve / reject both enforce PENDING-only transitions through `assertChannelPushTransition`; approve stores an APPROVE action with optional `comment`, reject stores a REJECT action with required `comment`.
    - Review actions never create VisitRecord, ApprovalApplication, or Notification records.
    - Serialized review rows include `channelPartnerName`, `reviewedAt`, `reviewComment`, `internalScheduledReceiverName`, `internalScheduledDate`, `internalNote`, `attachmentCount`, and the existing student/status fields.
    - Serialized review detail includes the row fields plus `attachments`, `reviewActions`, and `duplicateHints`.

    Use the existing `prisma` singleton and reuse `serializeChannelPushDetail` only where its audience-aware shape is still correct. Add focused bun tests that pin the recipient scope, derived timestamps/comments, internal-field persistence, duplicate-hint shape, and REVIEW-06 negative assertions.
