## 分组创建与结构编辑

### Q1: 如何在设计器添加分组？

| Option | Description | Selected |
|--------|-------------|----------|
| 字段面板新增"结构"组 | 与字段拖拽体验统一，拖入画布自动创建空分组（默认标题"分组标题"）；改动最小 | ✓ |
| 画布工具栏按钮添加 | 画布顶部独立按钮，点击即在当前位置插入空分组；与现有拖拽范式不一致 | |
| 右键菜单插入 | 依赖隐藏交互，不够直观；新用户难发现 | |

**User's choice:** 字段面板新增"结构"组

### Q2: 分组内的行/字段如何编辑？

| Option | Description | Selected |
|--------|-------------|----------|
| 分组内完全复用行编辑逻辑 | 抽取 DesignerCanvas 行编辑为可复用组件/递归渲染，UX 一致（行拖拽、colSpan resize、叠加行等） | ✓ |
| 分组内只支持单行字段 | 只允许拖入字段、调整 colSpan、删除，不支持多行；简化但限制多 | |
| 分组内容在属性面板编辑 | 属性面板提供表格式添加字段；脱离画布拖拽范式 | |

**User's choice:** 分组内完全复用行编辑逻辑

### Q3: 字段能否跨分组边界拖拽？

| Option | Description | Selected |
|--------|-------------|----------|
| 允许自由跨组拖拽 | 用户可从组外拖字段进组，或从组内拖出；符合直觉；vue-draggable-plus group:'fields' 同名机制已支持 | ✓ |
| 禁止跨组拖拽 | 字段不能主动跨组，需先删后加；操作刮手 | |
| 仅允许拖出组，不允许拖入组 | 语义有些断裂 | |

**User's choice:** 允许自由跨组拖拽

### Q4: 分组的整体排序方式？

| Option | Description | Selected |
|--------|-------------|----------|
| 分组有拖拽手柄可上下排序 | 分组作为独立块、左侧有拖拽手柄（复用 Phase 11 行手柄 UX），与行在顶层 items[] 平等排序 | ✓ |
| 分组不可排序 | 创建时位置固定，需调整顺序先删后加；灵活性低 | |
| 属性面板"上移/下移"按钮 | 与行拖拽交互不一致 | |

**User's choice:** 分组有拖拽手柄可上下排序

## 分组属性与标题编辑

### Q5: 分组标题在哪里编辑？

| Option | Description | Selected |
|--------|-------------|----------|
| 右侧属性面板编辑 | 分组选中时右侧属性面板显示标题输入框 + 删除按钮；与字段属性编辑模式统一 | ✓ |
| 画布内联双击编辑 | 双击分组标题栏进入编辑，失焦保存；更直观但需额外交互逻辑 | |
| 两者都支持 | 属性面板和画布双击都可编辑；复杂度最高 | |

**User's choice:** 右侧属性面板编辑

### Q6: 创建新分组时的默认标题处理？

| Option | Description | Selected |
|--------|-------------|----------|
| 直接创建空分组 + 默认标题 | 拖入即创建标题为"分组标题"的空分组，用户选中后编辑；与字段拖入后编辑 label 体验一致 | ✓ |
| 弹框要求输入标题 | 拖入后弹出小弹框要求用户输入；中断拖拽节奏 | |
| 创建后自动聚焦 | 拖入后自动聚焦标题输入框；实现需跨面板聚焦 | |

**User's choice:** 直接创建空分组 + 默认标题

### Q7: 分组是否支持额外特性（折叠/样式）？

| Option | Description | Selected |
|--------|-------------|----------|
| 不支持，仅表格外观 | 与 GroupRenderer 现有 UI 保持一致（标题栏 + 内容区），不引入额外复杂度；REQUIREMENTS 未要求 | ✓ |
| 支持折叠/展开 | 添加折叠按钮，填写页可折叠；v1.2 未要求，增加填写页渲染复杂度 | |
| 支持样式自定义 | 颜色/边框样式选项；超出 Phase 12 核心需求（属于 v2） | |

**User's choice:** 不支持，仅表格外观

### Q8: 分组删除时的行为？

| Option | Description | Selected |
|--------|-------------|----------|
| 直接删除，不弹确认 | 与 Phase 11 D-13 字段删除不弹确认 UX 一致；可通过撤销/重拖恢复 | ✓ |
| 弹框确认删除 | 安全但与字段删除 UX 不一致 | |
| 删除时提升内部行 | 删除分组容器但保留内部行到顶层；语义敏感 | |

**User's choice:** 直接删除，不弹确认

## 动态表格列结构定义

### Q9: 动态表格的列结构在哪里编辑？

| Option | Description | Selected |
|--------|-------------|----------|
| 属性面板内嵌列列表编辑器 | 选中表格后属性面板显示列列表（label、type、width，可增删/排序）；与字段属性编辑模式统一 | ✓ |
| 独立抽屉/弹窗编辑列 | 点击"编辑列"打开抽屉；面板空间有限时更友好但提高模态复杂度 | |
| 画布内列头点击编辑 | 画布内表格预览直接点击列头编辑；所见即所得但结构复杂 | |

**User's choice:** 属性面板内嵌列列表编辑器

### Q10: 动态表格列支持哪些字段类型？

| Option | Description | Selected |
|--------|-------------|----------|
| 精简子集：text / radio / checkbox / date / phone | 动态表格列通常短文本；textarea/signature 行内体验差；简化实现 | ✓ |
| 全部 7 种字段类型 | 包括 textarea/signature；行内不实用，实现复杂度和布局弹性冗余 | |
| text / date 小集 | 最简单但功能受限（如表格内无法选择性别） | |

**User's choice:** 精简子集：text / radio / checkbox / date / phone

### Q11: 动态表格的列宽方案？

| Option | Description | Selected |
|--------|-------------|----------|
| Flex 比例（类似 flex-grow） | 列宽用相对比例（默认 1，可调 1-6），CSS Grid/Flex 布局；与 12 列栅格哲学一致 | ✓ |
| 百分比宽度 | 每列用百分比；需用户自行算总和 100% | |
| 全部等宽，无法调整 | 最简单但用户没有布局控制权 | |

**User's choice:** Flex 比例（类似 flex-grow）

### Q12: 新建动态表格时的默认列配置？

| Option | Description | Selected |
|--------|-------------|----------|
| 默认 2 列 text | 拖入即生成 2 列 text（label: "列 1"/"列 2"），用户马上看到表格雏形；降低上手成本 | ✓ |
| 默认 0 列，用户手动添加 | 新建时 columns 为空数组，画布显示"请添加列"提示；不够直观 | |
| 拖入时弹框配置初始列 | 拖入时弹窗让用户配置列数 + 列名；打断拖拽节奏 | |

**User's choice:** 默认 2 列 text

## 动态表格填写交互与数据格式

### Q13: 填写页动态表格的行增删 UI？

| Option | Description | Selected |
|--------|-------------|----------|
| 每行右侧删除图标 + 底部添加行按钮 | 行尾有删除图标（悬停显示），表格底部固定"+ 添加行"按钮；符合 Excel/表格组件常规 | ✓ |
| 每行 +/- 操作列 | 最右侧固定操作列，每行 +/- 按钮；操作更灵活但 UI 空间占用更多 | |
| 右键行菜单操作 | 默认隐藏删除，右键弹菜单；发现性差 | |

**User's choice:** 每行右侧删除图标 + 底部添加行按钮

### Q14: 填写页动态表格的初始行数？

| Option | Description | Selected |
|--------|-------------|----------|
| 默认 1 行 | 初始 1 行空值，用户看到表格格式即可填写；降低上手成本；无需设计器额外配置 | ✓ |
| 默认 0 行 | 必须添加才能填写，不够直观 | |
| 可配置 minRows | 设计器属性面板提供 minRows 字段；v1.2 不必要的灵活性 | |

**User's choice:** 默认 1 行

### Q15: 填写表格提交数据结构？

| Option | Description | Selected |
|--------|-------------|----------|
| 数组 + 列键值对象 | `submission.data[tableId] = [{colKey1: val, colKey2: val}, ...]`；列用 colKey 索引，宽容后期加列/删列 | ✓ |
| 二维数组 | `data[tableId] = [[val1, val2], ...]`；与 columns[] 下标按顺序对应；调整列顺序后旧数据错位 | |
| 包含列元数据的对象 | `data[tableId] = { rows: [...], cols: [...] }`；类似 Excel 文件格式，但反序列化/查看更复杂 | |

**User's choice:** 数组 + 列键值对象

### Q16: Print 模式（提交详情 + PDF）动态表格的渲染方式？

| Option | Description | Selected |
|--------|-------------|----------|
| 原生 HTML table | `<table>` + border (`table-layout: fixed`) 渲染；与 Phase 13 PDF 导出（jspdf-autotable）天然兼容；承袭 v1.1 打印传统 | ✓ |
| CSS Grid 布局 | 用 CSS Grid 绘制表格样式，顺应 GridFormRenderer 体系；html2canvas/PDF 对 CSS Grid 支持历史问题 | |
| 卡片列表 | 表格转换为每行为一张卡片的列表；与 RENDER-03"表格"需求不符，且 Phase 14 才处理移动端卡片化 | |

**User's choice:** 原生 HTML table
