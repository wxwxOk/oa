  <action>
在本地（非 Docker）验证后端全链路：

1. 确保 PostgreSQL 在 localhost:5432 可用（通过 docker compose 的 postgres 服务，或本地安装）。
   如果 postgres 容器未运行，执行：`cd /e/webspace/oa && docker compose up -d postgres`，等待 healthy。

2. 在 backend 目录执行数据库迁移和 seed：
   ```bash
   cd /e/webspace/oa/backend
   bunx prisma generate
   bunx prisma migrate deploy
   bun run prisma/seed.ts
   ```
   验证输出包含 "seed 完成: admin / admin123"。

3. 启动后端（后台）：
   ```bash
   cd /e/webspace/oa/backend
   bun run src/index.ts &
   ```
   验证输出包含 "OA backend running"。

4. 测试 login 端点：
   ```bash
   curl -s -X POST http://localhost:3000/api/v1/auth/login \
     -H "Content-Type: application/json" \
     -d '{"username":"admin","password":"admin123"}'
   ```
   验证响应包含 `accessToken`、`refreshToken`、`user.roles` 包含 "ADMIN"。

5. 用返回的 accessToken 测试 profile 端点：
   ```bash
   curl -s http://localhost:3000/api/v1/auth/profile \
     -H "Authorization: Bearer <accessToken>"
   ```
   验证响应包含 `username: "admin"`。

6. 用返回的 refreshToken 测试 refresh 端点：
   ```bash
   curl -s -X POST http://localhost:3000/api/v1/auth/refresh \
     -H "Content-Type: application/json" \
     -d '{"refreshToken":"<refreshToken>"}'
   ```
   验证响应包含新的 `accessToken`。

7. 测试用 accessToken 调用 refresh 应失败（type 校验）：
   ```bash
   curl -s -X POST http://localhost:3000/api/v1/auth/refresh \
     -H "Content-Type: application/json" \
     -d '{"refreshToken":"<accessToken>"}'
   ```
   验证响应状态码 401。

8. 停止后端进程。

如果任何步骤失败，检查错误日志并修复 `backend/src/index.ts` 或相关文件中的问题。常见问题：
- Prisma Client 未生成：执行 `bunx prisma generate`
- 数据库连接失败：检查 `backend/.env` 中 DATABASE_URL 使用 localhost
- JWT 相关错误：检查 accessJwt/refreshJwt 注册是否正确
