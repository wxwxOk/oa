# Milestone v1.3: 到访信息管理

**Status:** SHIPPED 2026-05-02
**Phases:** 20-23
**Total Plans:** 10
**Validation:** automated tests/builds passed; user confirmed manual testing passed

## Overview

新增固定的到访信息管理模块，承接《渠道往来测试表.xlsx》中的学员到访、咨询接待、试听跟进和成交状态管理。v1.3 使用固定 `VisitRecord` 业务表，不复用自定义表单 JSONB；Excel 只支持导入，统计只做系统内概览。

## Phases

### Phase 20: 到访数据模型 + 后端 API

**Goal**: 建立到访固定业务模块的数据层、权限体系和后端接口，供前端页面和导入功能复用。
**Depends on**: Phase 19 (v2.0 implemented)
**Requirements**: VISIT-01, PERM-01, PERM-02
**Plans**: 3 plans

Plans:

- [x] 20-01: Visit permission, route, import and stats backend contracts
- [x] 20-02: VisitRecord Prisma model, migration and permission seed
- [x] 20-03: `/api/v1/visits` CRUD, filters, JSON import and stats endpoints

**Details:**
- `VisitRecord` maps the 15 sample-sheet business fields plus `creatorId`, timestamps and common indexes.
- Seed data includes `visit:list/create/update/delete/import/stats`; ADMIN inherits all permissions.
- `visitModule` is registered under `/api/v1/visits` and guards each endpoint with the matching `visit:*` permission.
- Write/import schemas accept only explicit business fields; `creatorId` is derived from the authenticated user.

### Phase 21: 到访管理页面 + CRUD 筛选

**Goal**: 交付可日常使用的到访管理页面，支持记录维护、筛选和响应式查看。
**Depends on**: Phase 20
**Requirements**: VISIT-02, VISIT-03, VISIT-04, QUERY-01, QUERY-02, QUERY-03, QUERY-04
**Plans**: 3 plans

Plans:

- [x] 21-01: Frontend visit DTO/store/page contracts
- [x] 21-02: Visit types, Pinia store, route and menu wiring
- [x] 21-03: Responsive visit page, table/cards, filters and CRUD dialogs

**Details:**
- `/visits` is a top-level menu entry gated by `visit:list`.
- PC uses QTable; mobile uses cards; long text stays in detail/edit dialogs.
- Filters cover keyword, channel partner, consultant, receptionist, reception status, consultation status, status category and reception date range.
- Create, edit and delete actions are independently gated by `visit:create/update/delete`.

### Phase 22: Excel 导入解析 + 预览入库

**Goal**: 支持导入《渠道往来测试表.xlsx》格式，将存量 Excel 台账安全转为系统到访记录。
**Depends on**: Phase 20, Phase 21
**Requirements**: IMPORT-01, IMPORT-02, IMPORT-03, IMPORT-04
**Plans**: 2 plans

Plans:

- [x] 22-01: `xlsx` dependency, fixed 15-column parser and parser tests
- [x] 22-02: Import store action, preview dialog and `visit:import` page entry

**Details:**
- Frontend parses the first sheet with SheetJS/FileReader, ignores row 1, validates the 15-column header row at row 2 and parses row 3 onward.
- Preview separates valid rows, invalid rows and error reasons.
- Potential duplicates are warning-only, keyed by `姓名 + 接待日期 + 咨询师`; no auto-skip, merge or upsert is introduced.
- Confirm import posts normalized JSON rows to `/visits/import`; the backend revalidates and derives attribution.

### Phase 23: 统计面板 + 转化汇总

**Goal**: 为管理者提供渠道、人员和状态维度的到访质量与转化概览。
**Depends on**: Phase 20, Phase 21
**Requirements**: STAT-01, STAT-02, STAT-03, STAT-04
**Plans**: 2 plans

Plans:

- [x] 23-01: Enriched backend stats DTO and contract tests
- [x] 23-02: Visit stats frontend panel, store action and page integration

**Details:**
- `/visits/stats` remains guarded by `visit:stats` and filters by `receptionDate` via `dateFrom` / `dateTo`.
- Backend owns intent/signed counts and rates; frontend formats returned metrics.
- Channel partner, consultant and receptionist dimensions include total, intent, signed and conversion rates.
- Reception status, consultation status, status category and trial status are returned as distributions.
- Blank/null/whitespace buckets are grouped as `未填写`.

## Milestone Summary

**Key Decisions:**

- Use a fixed `VisitRecord` table for the stable visit ledger instead of dynamic form JSON.
- Store status-like fields as nullable strings; dictionaries/enums remain future scope.
- Keep Excel parsing frontend-only and submit normalized JSON to the backend.
- Treat duplicate import detection as a warning, not an automatic merge/upsert rule.
- Keep stats backend-owned for consistent intent/signed calculations.
- Gate the visit module with dedicated `visit:*` permissions across backend and frontend.

**Issues Resolved:**

- Added the complete visit data model, migration, permission seed and API module.
- Added daily-use CRUD, filtering and responsive UI.
- Added safe Excel import preview and batch creation.
- Added management statistics for channel, personnel and status dimensions.

**Issues Deferred:**

- Excel export, follow-up reminders, dictionaries, automatic dedupe/merge, sales workflow and public signup remain future requirements.
- v2.0 Phase 18 milestone verification remains tracked separately and was not changed by v1.3 archival.

**Technical Debt Incurred:**

- Some Phase 20-22 task summaries note inline execution in a dirty worktree rather than atomic task commits.
- Full end-to-end visit test data fixtures remain lightweight; manual testing covered the shipped flow.
